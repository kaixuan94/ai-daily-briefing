1.2 「Quick fix 有害论」：别总让 Agent 做最小改动

  • 核心观点：@poteto 提醒：你要求 Agent 做「最小、最快的改动」时，可能在让它写更差的代码。看似无害的创可贴补丁，会被下一个 Agent 当成模式照抄，不知不觉就在代码库里扩散开。
  • 关键方法/工具：代码库里的模式会被 Agent 复制，坏模式也一样。
  • 可行动点：给 Agent 的提示里少写「最小改动」，多写「按正确的方式修，并顺手清理同类问题」；在 code review 里专门留意临时补丁。

1.4 Skill 就像函数；必须确定性的流程别用 Skill

  • 核心观点：@housecor：Skill 像函数：做一件具体的事、接收参数、有一个或多个输出、可以手动调用或定时调度、可组合（Skill 能调 Skill）、可以分享给团队或公开。另一条补充：如果一个流程必须是确定性的，Skill 就不是正确答案，应该写代码。
  • 关键方法/工具：Skill 设计原则。
  • 可行动点：梳理自己的 Skill：确定性步骤（格式转换、部署）沉到脚本里，Skill 只负责需要判断的部分。
