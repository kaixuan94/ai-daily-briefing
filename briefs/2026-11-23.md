### 1.3 Agent 验收：宝玉的五条经验
- **核心观点**：@dotey 针对「Agent 说验证完了却没做好」给出五条经验（收藏 258）：① 别依赖对抗式验证，多个 Agent 互相挑刺往往越改越偏，因为缺统一的验收标准；② 给清晰的验收标准和能验收的环境，比如「做完截图和设计稿对比，像素一个不差」，它就会自己写工具对比、返工；③ 越早验证越好，先做可行性分析、原型和技术方案文档；④ 让 Agent 提供截图、前后对比、可视化 HTML 报告当证据，降低人的验收成本；⑤ PR 尽量小，让 Agent 先审，人只盯 P0、P1 级别的问题。
- **关键方法/工具**：验收标准 + 验收环境；截图/录屏证据；分级代码审查。
- **可行动点**：下次给 Agent 派任务时，在最后补一句「完成标准是 X，请用 Y 方式自证」。

### 1.4 把约束写进代码：Lauren Tan 的分享与 poteto 的 pstack 提示词
- **核心观点**：@huxlab 转述 Lauren Tan 在 AI Engineer Code Summit 的分享：她上个月一个人往生产环境合了 3000 个 PR（全团队 1.1 万个），回滚率约 0.5%。做法是：代码库本身才是最大的输入，直接封死容易出错的路径（比如产品代码禁用 useEffect）；Agent 每犯一次错就改成 Lint 或架构约束，而不是改 AGENTS.md；强制 Agent 用测试、截图、录屏自证；按「代码库约束 > 静态分析 > 运行时验证 > 人工 Review」搭信任金字塔。@poteto 分享的 pstack 提示词（点赞 2243、收藏 1453）思路相同：读 git log、历史 bug 修复和 review 评论，找出反复出现的错误，再按架构、类型、Lint、测试的顺序让它们「不可能再犯」，删掉复述代码的注释。
- **关键方法/工具**：Lint 化纠错；信任金字塔；pstack / poteto-mode 提示词。
- **可行动点**：把最近三次 Agent 犯的错各写成一条 Lint 或测试。
- **原帖链接**：https://x.com/huxlab/status/2124431893399830605 ；https://x.com/poteto/status/2124525336994177412
- **来源标注**：【账号池】@huxlab、@poteto
