1.5 Claude Code 团队怎么做「验证」

  • 核心观点：@vikingmute 推荐 Addy Osmani 的《How the Claude Code team thinks about verification》：用验证闭环让 AI 大量写代码和审代码，最值得投入的三类测试是 E2E、Property 测试和 Differential 测试，后面有很细的 verify 步骤。@xiaomovps 也结合自己用 Pi、DSH、Codex 的经验写了读后感。
  • 关键方法/工具：E2E + Property-based + Differential 测试构成验证闭环。
  • 可行动点：给自己的 Agent 项目至少补一层 E2E 和一组 Property 测试，让 AI 改代码时有客观「验收」。
  • 原帖链接：https://x.com/vikingmute/status/2122693797431898566 ；https://x.com/xiaomovps/status/2122642096385577102
  • 来源标注：【账号池】@vikingmute、@xiaomovps

1.6 Agent 工具约束实验 + 「人类审查」规则

  • 核心观点：@mattpocockuk 的实验：既然选择太多对 Agent 不好，那就做「极度受限」版的工具栈（例如允许用 React，但所有状态必须放 Zustand/useReducer）。@housecor 团队新规定：被请求做代码审查时必须是人工审查，不允许贴 AI 评论；但他也承认很多团队还没成熟到取消人工审查，需要先补自动化检查。
  • 关键方法/工具：给 Agent 收窄技术选择；人审与 AI 审分开。
  • 可行动点：在项目规则文件里写死技术栈约束，减少 Agent 乱选；明确哪些审查必须由人做。
  • 原帖链接：https://x.com/mattpocockuk/status/2122659341685694586 ；https://x.com/housecor/status/2122676634084057189 ；https://x.com/housecor/status/2122763219852812317
  • 来源标注：【账号池】@mattpocockuk、@housecor
